# Research/reference edition policy

The distinct research policy remains disabled (`publication_enabled: false`). The current canonical inventory has zero authenticated real item approvals. The unchanged legacy local-build exception is not authorization for a new public edition.

The [authenticated workflow](RESEARCH_APPROVAL_WORKFLOW.md) requires item-bound metadata rights, extractive review, factual review, classification, publication and conditional native Bangla decisions. Every stage binds exact content, source, rights, translations, environment, ledger and policy. Existing editorial dimensions remain mandatory. Expiry, revocation, source withdrawal, STOP, changed evidence and unauthenticated custody deny eligibility. A typed name, local manifest, source allowlist or config flag grants no authority.

Canonical input: 37 unchanged records, SHA-256 `d146d528ed8b00bc4e3a1e379ceffa300f46ce5a17ee9d34e8291410e9973eb5`. Private item packets and signed operational records stay outside Git and public assets. Proposed editorial repairs need separately reviewed revisions and new approvals. Research preprints need truthful peer-review/replication limitations. Reference documents need captured revision and verification time; missing publication dates stay unknown. No paper bodies or figures are included by implication. English UI fallback grants no native Bangla approval.

`pnpm build:research` retains the isolated synthetic rehearsal. `pnpm build:research --real` builds only a local candidate using the existing Python verifier for the exact snapshot. It refuses by default. Once separately authorized policy, authentic human decisions and independent custody genuinely exist, it selects only eligible records, closes their citation set and drops precomputed digests, offers, model trackers, archives and unrelated sources. It refuses private or unapproved cited evidence. Search, RSS, sitemap, direct routes and attribution use that filtered snapshot. The canonical input is never edited.

Both profiles write `apps/web/dist-research`, isolated from ordinary output. The real candidate notice differs from the explicit synthetic rehearsal notice. Every research profile remains noindex/no-store with same-origin CSP and no analytics/public environment injection. Provenance binds source, input, output and profile. Fresh authorization verification after build catches withdrawal or emergency freeze during construction.

Noindex is not access control. Candidate assets stay local until separately authorized for an exact preview destination. `verify-research --publish` always refuses: local verification does not authorize deployment. Existing `deploy` and `deploy:preview` retain their news/release gates. Research/reference material cannot satisfy the current-news gate. A public research release requires a separately reviewed publication/deployment packet and exact-SHA owner approval; no fallback publish switch exists.
