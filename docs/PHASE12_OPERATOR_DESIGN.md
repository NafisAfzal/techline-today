# Offline newsroom operator workflow

The operator surface reuses the existing signed registry, source dossiers,
editorial/translation states, observation receipts and recovery packs. It adds
preparation and rehearsal; it cannot establish real custody or grant rights.

| Boundary | Reused component |
|---|---|
| Source evidence | `source_onboarding`, `source_evidence` |
| Reviewer decisions | `authority.protocol`, `authority.registry`, `authority.ledger` |
| Editorial and Bangla | `editorial_workflow`, `translation_governance`, exact signed bindings |
| Checkpoints | Existing owner-signed checkpoint and journal comparison |
| Publication | Existing composite gate and production authority loader, unchanged |
| Build | Generation lock, governance, rights checks and provenance, unchanged |
| Observation and readiness | Existing receipts, elapsed-window evaluator and newsroom report |
| Recovery | Existing inventory, allowlisted pack format and isolated drills |

The proposed current-head protocol uses existing canonical JSON conventions,
SHA-256 and standard Ed25519, with a separate signature domain. A response binds
custodian/key identity, environment, ledger, complete challenge digest, signed
owner checkpoint digest, journal head/count, registry revision and a bounded UTC
lifetime. Verifier nonces are generated by `secrets`, never accepted from a
response. A mock session consumes each request once, detects clock/revision
regression and freezes after rejection. Replacing a pending request invalidates
the lost response. Unknown or rotated custodian keys are refused until a separate
trusted-key decision; no automatic trust-on-first-use or rotation discovery.

This session state is **process-local synthetic evidence**. Restarting or
compromising the process can reset its history and clock. A compromised custodian
can conceal a newer head; signatures alone cannot establish honesty. Real use
requires independently controlled custody, authenticated key/rotation history,
durable replay and monotonic state outside the compromised operator boundary,
an authenticated clock and a reviewed availability/conflict procedure. Skew is
currently refused rather than silently tolerated. There is no network adapter,
external write or production trust promotion. Existing production checkpoint
adapters continue to refuse missing independent freshness.

For a small newsroom, offline encrypted-file signing with separately held backup
and out-of-band fingerprint checks is a practical ceremony proposal. A second
person should verify fingerprints where available; a sole owner must document
that limit. Hardware-token signing is an unimplemented option and cannot pass
the preflight. Owner-held offline receipts help recovery but do not answer a
fresh online challenge. Protected Git history or another receipt store needs a
separately authenticated root and independent administration; a local clone is
insufficient. Managed append-only custody may improve availability at additional
cost and operational complexity; no service is selected or registered here.

Reports are stdout-only. Redirect private operator reports outside the checkout;
never add them to Astro assets. Ceremony confirmations are declarations for human
verification, not proof of device security, identity, backup or independent custody.
