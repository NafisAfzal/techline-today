# Source and Editorial Policy

## Source classes

### Primary
Official company/research lab blog, product docs, changelog, model card, regulator filing, official repository release.

### Independent reporting
Established publication or researcher reporting with original work.

### Aggregator/syndication
Useful for discovery, but should not increase independent source count if it repeats another report.

### Community
Hacker News, forum, Reddit-like discussion, social posts. Useful for sentiment/discovery only unless the post itself is the primary announcement.

## Selection principles

Prefer:
- meaningful product/model releases;
- substantial pricing/API changes;
- benchmark or research changes with evidence;
- security incidents with concrete user impact;
- time-sensitive free developer opportunities;
- material chip/device changes;
- open-source releases developers can use.

Deprioritize:
- minor marketing partnerships;
- recycled opinion pieces;
- rumor without credible evidence;
- engagement bait;
- repeated articles with no new fact.

## `What others say`

This section must attribute views to named sources. It should not manufacture a false debate or present all opinions as equally evidenced.

## Benchmarks

Separate:
- vendor-reported benchmark;
- benchmark reproduced by an independent party;
- community anecdote;
- real-world product metric.

Record task, benchmark version and hardware/context when the source provides them.

## Free offers

Never state `free` without qualifying important constraints such as:
- trial only;
- request/token limit;
- student eligibility;
- billing account/card required;
- country restriction;
- expiry;
- data-use conditions.

## Headline style

Good:
`Provider releases Model X with a 128K context window and free developer tier`

Bad:
`This INSANE new AI just destroyed every model`
