# Internal pilot attribution and editorial specification

`pipeline/pilot_attribution.py` produces an internal JSON presentation contract from normalized items, exact review bindings and optional operator-recorded evidence. It is not an article or public rendering model. The approved interface, routes, CSS and reader copy are unchanged.

Cross-source IDs, mismatched URLs/content hashes and mismatched decisions raise. Source publisher identity comes from the reviewed registry. Untrusted feed bylines and license assertions are not established creator/license evidence. Missing original publication, creator or license remains null. Every contract includes a rights evaluation denying publication and AI.

Contract version 2 preserves binding provenance (`synthetic` or `unknown`), proposed `permitted_fields`/`permitted_transformations`, scoped evidence URLs, obligations and exceptions. Missing scope is empty. Provenance is independent of licensing and editorial labels. No trusted real-world attestation exists in this inactive workflow; an unmarked item stays unknown. Item/binding/decision provenance contradictions reject. Local provenance/internal contracts are rejected by the public JavaScript rights gate, including if someone substitutes an otherwise allowed source ID. The established public snapshot schema and canonical edition remain unchanged.

The latest authoritative ledger event supplies both review metadata and rights state. `review_decision` includes the exact event/head hashes, policy, reviewer metadata, timestamps and evaluation reason. `rights_status` distinguishes unknown, review-required and denied; no approved state exists. A supplied decision without ledger history appears explicitly in `proposed_review`, with `review_decision=null` and `missing_record` rights. Its claims remain recorded-unapproved proposals. Superseded cached decisions cannot override history. Expired, future, revoked, rejected, changed-policy and changed-evidence records have their claims quarantined and active creator/license/scope fields unresolved. Reviewer strings and evidence links do not authenticate a reviewer or establish permission.

## Kubernetes

| Field | Required interpretation |
|---|---|
| `publisher` | Kubernetes Blog registry identity; does not establish original authorship |
| `canonical_source`, `required_attribution_link` | Exact normalized source item URL |
| `original_publication_url`, `original_creator` | Unknown unless separately scoped operator evidence is supplied; then explicitly recorded-unapproved |
| `applicable_license`, `license_evidence_urls` | Item-specific operator evidence only, still unapproved; no inferred footer/site-wide grant |
| `attribution_obligations`, `license_exceptions` | Recorded constraints that must be checked before any future publication |
| `modification_notice` | Discloses local normalization/shortening; future published adaptations need confirmed change notices |
| `rights_observation_state` | Held/rejected normalized observation, separate from an operator decision |
| `editorial_classification` | Source-reported announcement; not independently verified journalism |

A valid post timestamp is retained only when the source supplies a known time. Original creator, license scope, mirrors, guest contributions and exceptions remain unresolved unless evidence establishes them. No absence of markers or domain match licenses reuse.

## CISA KEV

The contract preserves exact CVE syntax, `catalog_added_on`, optional `remediation_due_on`, the original CISA catalog search link, and classification as official single-source security advisory intelligence. It carries no publication timestamp or fabricated time of day.

Required labels are generated by the existing date contract:

- “Added to the CISA KEV catalog on {date}”
- “CISA remediation due date: {date}” when supplied

Neither is a vulnerability disclosure, discovery, exploitation or vendor-announcement date. A remediation deadline's applicability/context must be reviewed before publication; no directive version, patch date, CVSS or severity is inferred. `breaking_news` and `independently_verified` are false.

Third-party links remain separate-rights, link-only references. The adapter does not retain vendor reference identities; the contract explicitly records `status=unresolved`, `vendor_identity=null` and an empty URL list. The simulator does not fetch or excerpt them. No logos, seals or endorsement claims are introduced. Advisories never satisfy the current-news production gate.

## Future presentation review

A future isolated article mock should show publisher, source link, verified creator where established, applicable license link, required attribution, modification notice, advisory date labels and explicit single-source provenance. It must be reviewed using an actually eligible item and the applicable obligations before public rendering is connected. Synthetic contracts demonstrate field propagation; they establish no real permission or creator identity.

End-to-end tests run synthetic ingestion through normalization, binding, operator evidence and the internal contract, then verify that the existing JavaScript rights gate rejects it as local-only evidence. No pilot content is published by these tests.
